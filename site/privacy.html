Privacy

Kiri never sends your files, their names or anything you type. To get better, it can send three things, all of them anonymous: reports when it crashes, counts of which features are used, and feedback you write yourself. The first two can be turned off with one switch each.

Crash reports

On until you turn it off. Where in Kiri's code a crash or a freeze happened.

Usage analytics

On until you turn it off. Which features, settings and languages get used.

Feedback

Only when you send it. Your words, and a screenshot if you add one.

How to turn it off

Open Kiri ▸ Settings… (⌘,) and find Privacy. Turn off Crash reports, Usage analytics, or both. It takes effect at once: Kiri stops sending that kind of data, and anything of that kind still waiting to be sent is deleted from your Mac.

On a Mac you manage from the terminal, the same switches are:

defaults write se.hellsoft.kiri crashReports -bool false
defaults write se.hellsoft.kiri usageAnalytics -bool false

Feedback has no switch because nothing is sent unless you write something and press Send.

What anonymous means here

  • Kiri makes a random id the first time it runs, so reports from the same Mac can be told apart from others. It is not tied to you, your Apple account, your Mac's serial number or any other app. The server stores only a scrambled version of it.
  • Kiri never asks for or sends a name, an email address or an account. The feedback form has no email field.
  • Your IP address is not stored.
  • Nothing contains a file's name, a folder's name, a path you opened or any text from a document.
  • To start over with a new random id: defaults delete se.hellsoft.kiri se.hellsoft.vaka.anon_id, then restart Kiri.

Crash reports

When Kiri crashes, it writes a small report on your Mac and sends it the next time it starts. When Kiri stops responding for two seconds or more, it sends a report about that freeze. A report has:

  • The kind of crash (such as EXC_BAD_ACCESS) and the call stack: memory addresses in Kiri and in the macOS frameworks it uses, with the names of those programs and libraries. Function names are filled in later on the server, from Kiri's own debug files.
  • Kiri's version and build, the macOS version, the Mac's model (such as Mac15,6) and processor type.
  • Which of Kiri's own windows were shown last (Settings, Keyboard Shortcuts, Send Feedback), and whether the session ended in a crash.
  • The random id described above.

One thing to know: if you keep Kiri in your own Applications folder inside your home folder, rather than the Mac's main Applications folder, the location of Kiri in a crash report includes your Mac user name.

Feedback

Help ▸ Send Feedback… opens a short form. What you write is sent as you wrote it, along with Kiri's version, the macOS version, the Mac's model and the random id. If Kiri crashed the last time, it asks what you were doing, and your answer is linked to that crash report.

The form can attach a screenshot of the Kiri window you were in. It is off until you turn it on, it shows you the picture first (click it to see it full size), and it includes whatever text is in that window, so look before you send. Only Kiri's own window is in it, never the rest of your screen. Feedback is sent even with crash reports and analytics off, because you asked to send it.

Where it goes and how long it stays

Everything goes to Vaka, a crash reporting and analytics service made and run by Hellman Software AB, the company behind Kiri. It is used only to find bugs and decide what to improve. It is never sold, never shared with anyone else and never used for advertising. Crash reports, analytics and feedback are deleted automatically after 90 days.

Kiri's update check is the only other thing that goes online: once a day it asks GitHub whether there is a new version (Settings ▸ Updates turns that off). It sends nothing about you.

Questions

Write to Hellman Software AB, or open an issue. Kiri's source is on GitHub, so you can read exactly what it sends in Telemetry.swift.
